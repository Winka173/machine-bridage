# Machine Brigade — notes for Claude

- Specification: `Docs/GAME_PLAN.md`. Architecture rules are in section 10 and acceptance cases in section 11. `Docs/RTS_GAME_PLAN*.md` are background only; their base-building scope is dropped.
- Unity 6000.6.3f1: `/c/Program Files/Unity/Hub/Editor/6000.6.3f1/Editor/Unity.exe`. Always launch Unity and Unity Hub with `env -u ELECTRON_RUN_AS_NODE`, because the VS Code environment sets it.
- Always pass `-nographics` to batch-mode Unity. Without it, Unity shares the GPU with the running emulator and the NVIDIA OpenGL driver crashes the emulator (`qemu-system-x86_64.exe` kernel exception).
- Unity builds kill the adb server when they finish; the next adb command restarts it and the emulator reconnects.
- The emulator's Vulkan does not work under ARM translation (black screen), so emulator images are denied Vulkan through `Assets/MachineBrigade/Settings/VulkanDeviceFilters.asset` and fall back to GLES3. Unity 6.6 no longer builds Android x86_64.
- Batch mode fails while the user has the project open in the editor. If a batch run reports that the project is locked, ask the user to close the editor.
- `-runTests` must not be combined with `-quit`. Read the results XML rather than the log.
- `MachineBrigade.Sim` has `noEngineReferences: true`. Never add `UnityEngine` usages there; put anything engine-facing in the Game layer.
- Unity 6.6 has its own `UnityEngine.EntityId`. In Game files, alias ours: `using EntityId = MachineBrigade.Sim.Core.EntityId;`.
- The project uses the Linear colour space. Vertex colours reach shaders unconverted, so pass mesh colours through `Primitives.Linear`. Material colours are converted by Unity automatically.
- The scene is generated by `MachineBrigade.Editor.SceneBuilder.Build`. Progress and known limitations are logged in `Docs/PROGRESS.md`.
- Scenes stay minimal. Spawn match content from code and JSON data instead of hand-editing scene YAML.
- For device testing, use the Android emulator AVD `Pixel_3a_API_35_extension_level_13_x86_64` (SDK at `%LOCALAPPDATA%\Android\Sdk`) with `Tools/run-android.sh`. It renders on the host RTX GPU, so emulator FPS says nothing about phone performance. Report emulator results as functional checks only.
- The user writes in Vietnamese. Reply in Vietnamese; code, comments and docs are in English.
- On OpenGL ES the URP SRP Batcher drew vehicles with stale transforms (turrets flashing back to an old pose, moving tanks stuttering). `Atmosphere` turns it off when `SystemInfo.graphicsDeviceType` is `OpenGLES3`; do not re-enable it there without measuring. `GraphicsSettings.useScriptableRenderPipelineBatching` is overwritten by URP every frame, so switch `UniversalRenderPipelineAsset.useSRPBatcher` instead.
- Rendering problems on the device are bisected with `Match.DebugFlags` switches (for example `-mb-no-shake`, `-mb-no-turret`, `-mb-no-srpbatcher`), passed as an intent extra: `adb shell am start -n com.winka.machinebrigade/com.unity3d.player.UnityPlayerGameActivity --es mbflags -mb-no-shake,-mb-no-post`. IL2CPP players do not see `-e unity` arguments in `Environment.GetCommandLineArgs`.
- To measure flicker, record with `adb shell screenrecord` (set `MSYS_NO_PATHCONV=1` in Git Bash for `/sdcard` paths) and count single-frame brightness spikes per screen region with OpenCV (`cv2` is installed; `ffmpeg` is not). Screenshots rarely catch one-frame artefacts.
- Blender 4.5 portable: `C:\Users\Winka\Tools\blender-4.5.14-windows-x64\blender.exe`. Models are built by `Tools/blender/build_assets.py`; overlapping coplanar faces between parts z-fight in game, so keep parts at least 1 cm apart.
- Quick device checks without tapping through the menu: `--es mbflags -mb-play` starts a Conquest match directly; add `-mb-survival`, `-mb-rain`, `-mb-storm` or `-mb-clear`. `adb shell input tap` sequences need about 1 s between a HUD card and a map tap, or the map tap lands before the card's click registers.
- Headless balance checks: `ConquestBattleTests` plays whole AI-versus-AI Conquest matches with the shipped content and logs length, captures, losses, deployed vehicles and strikes; read its log line after balance changes.
- Performance on the emulator: `-mb-perf` logs frame-time percentiles, hitches, engine markers (Recorder) and a scene census to logcat; `-mb-no-scenery`, `-mb-no-hud`, `-mb-no-fx`, `-mb-no-shadows`, `-mb-no-post`, `-mb-no-msaa`, `-mb-no-range` bisect costs, and `-mb-far` shows the far north-west scenery. The emulator caps at about 30 fps even with nothing drawn, so judge smoothness, not peak fps. Optimized Frame Pacing (Swappy) crashes the emulator (ARM translation), so `androidUseSwappy` stays 0.
- `Mathf.SmoothStep(a, b, t)` interpolates from a to b; it is not the shader `smoothstep(edge0, edge1, x)`. Use a proper edge function for thresholds (see `Surroundings.Edge`).
- URP's clip-space fog assumes a perspective camera; with the orthographic camera it did nothing on GLES. Shaders compute fog from view depth (`OrthoFog`).
- Ashfield is generated: edit `Tools/maps/build_ashfield.py` and run it (it checks reachability and warns about placements it cannot fit); `Tools/maps/plot_map.py <map.json> <out.png>` draws a map from above.
