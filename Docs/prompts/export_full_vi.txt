Bạn làm việc tự chủ trong repo Machine Brigade (Unity). Ghi quyết định vào docs/DECISIONS.md mục "Bộ xuất dữ liệu toàn bộ", mỗi lượt một hoặc vài commit. Prompt này THAY MỌI yêu cầu xuất dữ liệu / Excel / Markdown trước đó.

## 0. MỤC TIÊU
Tạo một công cụ xuất MỌI dữ liệu cấu hình và cân bằng của game ra một THƯ MỤC gồm nhiều file chia theo lĩnh vực (vũ khí, phương tiện, boss, căn cứ và tháp, chế độ và kinh tế, AI, chiến dịch và cốt truyện, bản đồ, hiệu ứng và âm thanh, model và tài sản, meta và giao diện, hệ thống và trạng thái). Dùng cho cân bằng khi phát hành và sau phát hành, kiểm tra chéo bằng công cụ khác, so sánh trước / sau mỗi bản vá.
"MỌI dữ liệu" = mọi giá trị mà người cân bằng có thể muốn xem hoặc đổi, kể cả thứ KHÔNG có trong danh sách của prompt này. Các danh sách ở mục 4 chỉ là TỐI THIỂU. Thừa còn hơn thiếu.
Nguyên tắc:
1. Tự khám phá nguồn dữ liệu, không liệt kê tay rồi bỏ sót.
2. Bài test độ phủ khóa: thiếu một trường là build fail.
3. Dữ liệu gốc xuất đúng như trong game; cột suy ra dùng đúng hàm của game khi có thể.
4. Chạy lại bằng một lệnh, nằm trong CI, xuất đồng nhất (cùng dữ liệu → cùng file).
5. KHÔNG đổi bất kỳ giá trị nào của game.

## 2. QUY TẮC CHUNG
2.1 Định dạng (người và máy đọc không lỗi):
- Mỗi sheet một bảng; DÒNG 1 là tên cột; không ô gộp, không dòng tiêu đề phụ, không dòng tổng.
- Cột đầu là id ổn định (cùng id với dữ liệu).
- Số lưu dạng số; đơn vị ghi ở TÊN CỘT (hp, speed_m_s, cooldown_s, range_m, cost_cp); không ghi "5 s" trong ô.
- Ô không áp dụng để TRỐNG; ô chưa làm: "CHUA_AP:prompt_N"; ô cần đọc mã mà chưa đọc: "NEED_CODE_CHECK".
- Danh sách đơn giản trong một ô ngăn bằng ";"; không lồng JSON trong ô; mỗi dòng có cột raw_json chứa nguyên bản ghi gốc để khôi phục.
- Cột trạng thái dùng tập giá trị cố định (ghi trong Schema).
- Cột _truoc / _sau cho mọi thứ vừa đổi (đọc từ git: so với bản xuất trước hoặc tag chỉ định); không dùng chuỗi "a → b".
- Mọi sheet có cột nguon (file + khóa nguồn / hàm / báo cáo sinh ra dòng đó).
- Sắp xếp dòng theo id, cột theo thứ tự cố định; không ghi mốc thời gian trong ô dữ liệu (chỉ README và MANIFEST).
- Sheet tối đa 31 ký tự, ASCII snake_case; tên tiếng Việt ghi ở sheet Muc_luc_sheet. Mỗi file xlsx dưới ~50 MB (vượt thì tách file con: <tên>_a, <tên>_b, ghi trong mục lục).
2.2 Liên kết giữa các file:
- Khóa ngoại bằng id (ví dụ weapon_id, vehicle_id, mission_id, map_id); mọi khóa ngoại trỏ tới id tồn tại ở file chủ (test).
- Công thức Excel CHỈ tham chiếu sheet CÙNG FILE (không dùng liên kết ngoài giữa các file).
- Số cần từ file khác (ví dụ DPS xe tham chiếu cho Boss_hieu_qua, giá xe cho tháp) được chép vào sheet input_<tên> trong file dùng, ghi nguon; test: input chép == giá trị ở file nguồn.
- Cùng (id, cột) không được có hai giá trị khác nhau ở hai file.
2.3 Cột suy ra là CÔNG THỨC EXCEL SỐNG tham chiếu sheet gốc / input cùng file (sửa số đầu vào thì kết quả đổi), kèm cột _game ghi giá trị do mã game tính; test: giá trị công thức == _game (sai số 1e-6) cho mọi dòng.

## 3. KHÁM PHÁ NGUỒN VÀ ĐỘ PHỦ KHÓA
3.1 Nguồn phải quét tự động; liệt kê tất cả vào sheet Nguon_du_lieu (file 00):
- balance.json, campaign.json và MỌI file JSON / CSV / TXT dữ liệu trong Assets, StreamingAssets, Resources, Tools;
- mọi ScriptableObject và Prefab có trường dữ liệu lối chơi (tốc độ, máu, tầm, hồi, bán kính, collider, mô tả hành vi);
- bảng localization;
- dữ liệu bản đồ (navmesh, tag, cứ điểm, bãi thả, căn cứ, ray, tuyến biển, vật thể, trung lập, địa danh, cổng vào, biến cố, thời tiết);
- dữ liệu âm thanh, VFX, model (GLB);
- dữ liệu meta (xu, giá nâng hạng, hòm đồ và tỷ lệ rơi, mở khóa, thưởng, nhiệm vụ ngày / tuần, mutator tuần, cửa hàng, thành tựu, hướng dẫn, thứ hạng, cài đặt mặc định);
- dữ liệu AI, thoại, nhân vật, trigger;
- telemetry nếu có.
Nguồn không đọc được: ghi vào Nguon_khong_doc_duoc kèm lý do.
3.2 Mỗi LOẠI thực thể một sheet, đặt vào file lĩnh vực hợp nhất; thực thể không rõ lĩnh vực vào 12_he_thong_trang_thai (sheet Khac_chua_phan_loai) và báo cáo. Dữ liệu lồng nhau phẳng hóa: danh sách con có id riêng thành sheet con nối bằng id cha (ví dụ Xe_vu_khi).
3.3 Test độ phủ khóa: duyệt MỌI đường dẫn lá (leaf path) trong mọi nguồn ở 3.1. Mỗi lá phải ánh xạ đúng vào MỘT cột của MỘT sheet, hoặc nằm trong Khong_xuat (mục 8) kèm lý do. Lá chưa ánh xạ: FAIL và in danh sách; thêm trường mới vào dữ liệu mà chưa xuất thì build fail.
3.4 Phủ ngược: mọi cột trong Excel truy được về một khóa nguồn (trừ cột suy ra; công thức nguồn ghi ở Schema). Phủ đối tượng: số dòng mỗi sheet bằng số thực thể trong dữ liệu; mỗi id đúng một dòng. Phủ tài sản: mọi prefab / SO / model / clip / bảng localization trong dự án có ít nhất một dòng.
3.5 COVERAGE.md (file 00): theo từng file lĩnh vực: số lá, số lá đã ánh xạ, số sheet, số dòng, số ô trống / cột, số ô CHUA_AP / NEED_CODE_CHECK; danh sách Khong_xuat; nguồn không đọc được.
