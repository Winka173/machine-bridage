# Machine Brigade — Game Plan v1 (Unity, mobile)

**Prepared:** 2026-09-26. **Engine:** Unity 6000.6.3f1 (Unity 6.6), URP. **Targets:** Android first, then iOS. **Bundle id:** `com.winka.machinebrigade` (previous working title: Tank Arena).

This is the primary specification for Machine Brigade. It replaces the base-building RTS described in [RTS_GAME_PLAN_V2.md](RTS_GAME_PLAN_V2.md), but keeps that document's architecture rules and the regressions that still apply (sections 10–11). Treat the V2 plan as background reading, not as scope.

Numbers in this document are prototype starting points to tune through playtesting.

## 1. Product brief

A 3D real-time tactics game on phones: the player commands **military vehicles only** (tanks, APCs, artillery, rocket launchers, anti-air, attack helicopters) in short battles against AI. There is **no base building, no economy management and no infantry**. The player calls vehicles and fire support in, pushes them into the fight, and watches the battlefield burn.

### Pillars

1. **Explosive spectacle.** Everything burns, breaks and chains. Wrecks stay burning, buildings crumble into voxel chunks, fuel depots take the block with them.
2. **Simple command.** Tap to select, tap to move, vehicles fire on their own. Drag a card to deploy or strike. No hidden controls.
3. **Short, varied matches.** 5–8 minutes. Several game modes built on the same core so new modes are cheap to add and tune.
4. **Runs on mid-range phones.** Explosions are budgeted and pooled from day one.

### Scope boundaries

- **In:** offline single-player against AI, several modes, 9 vehicle types, 8 fire-support types, voxel/low-poly art generated by code, English and Vietnamese.
- **Out until explicitly scheduled:** online multiplayer, infantry, naval units, base building, accounts, ads/IAP, analytics.
- **Success means:** a new player understands the controls within the first match, and the reference phone holds 30 FPS (Eco preset) with 40 vehicles and 30 simultaneous large explosions.

## 2. Core loop

```text
Choose mode, map, difficulty, loadout
          |
          v
Match: earn Command Points (CP) -> deploy vehicles / call strikes -> fight over objectives
          |
          v
Result screen: stats (damage, kills, things destroyed) -> unlocks -> next match
```

### Loadout (the "deck")

Before a match the player picks **6 vehicle cards and 2 support cards**. The deck is shown as a bar at the bottom of the screen during play.

### Command Points

- CP regenerate over time: **+1 CP/s** baseline, capped at **30 CP** banked.
- Bonus income per held objective (mode-defined, e.g. +0.3 CP/s per capture point).
- Kills grant **25% of the destroyed vehicle's CP cost**.
- Spending: deploying a vehicle, calling a strike. A destroyed vehicle refunds nothing; its card can be played again once affordable.
- **Unit cap:** each side fields at most **24 CP worth of vehicles** at once. This bounds performance and stops snowballing. Deploying above the cap is refused with a clear reason ("Army at capacity").

### Deployment

- Vehicles arrive at the side's **drop zone** after a short delivery (2–4 s): ground vehicles roll in from the map edge, helicopters fly in.
- If the drop zone is blocked, the vehicle waits and the card shows "Drop zone blocked". Cost is charged once, when the deployment is accepted.

## 3. Game modes

Every mode is a rule set on top of the same simulation. Modes observe simulation events and issue commands through the same API as the player and AI; **no unit contains mode-specific code**.

| Mode | Win condition | Milestone |
|---|---|---|
| **Conquest** (giữ cứ điểm) | 3–5 capture points. Each side starts with 300 tickets. The side holding fewer points loses tickets over time; kills also cost tickets. 0 tickets = defeat. | MVP |
| **Assault** (phá căn cứ) | Each side has a pre-placed HQ compound with turrets and walls (never built by the player). Destroy the enemy HQ core. | Phase 5 |
| **Survival** | Hold out against escalating AI waves; score by waves survived and damage dealt. Endless. | Phase 5 |
| King of the Hill | One central zone; first to 100% control wins. | Later |
| Convoy | Escort or intercept a convoy along a road. | Later |
| Free-for-all | 3–4 sides, last side standing or most points. | Later |
| Missions | Short scripted scenarios (hold the bridge, raid the depot) forming a light campaign. | Later |

### Mode contract

```csharp
public interface IGameMode
{
    void Setup(MatchContext context);          // place objectives, set tickets, spawn starting forces
    void Tick(MatchContext context, float dt); // runs inside the fixed simulation step
    void OnEvent(MatchContext context, in SimEvent e);
    MatchResult? CheckResult(MatchContext context);
}
```

Mode parameters (tickets, CP rates, wave tables, starting forces) live in data, so a mode can be tuned without code changes.

## 4. Vehicles and damage

### Damage model

Each weapon has a **damage type**. Each vehicle has an **armor class**. A multiplier table decides effectiveness. Counters are shown to the player as icons on cards and in the unit panel.

| Damage type \ Armor | Light | Heavy | Air | Structure |
|---|---:|---:|---:|---:|
| Kinetic (machine guns, autocannons) | 1.0 | 0.25 | 0.5 | 0.3 |
| Armor-piercing (tank guns, AT missiles) | 0.75 | 1.0 | 0.5 | 0.6 |
| High-explosive (artillery, rockets, bombs; splash) | 1.0 | 0.6 | 0.0 | 1.5 |
| Fire (damage over time, ignites terrain) | 1.25 | 0.5 | 0.0 | 1.0 |
| Flak (anti-air) | 0.4 | 0.1 | 1.5 | 0.1 |

### Roster

| Vehicle | Armor | CP | HP | Speed (m/s) | Weapon | Range (m) | Role / notes | MVP |
|---|---|---:|---:|---:|---|---:|---|:---:|
| Scout jeep | Light | 2 | 120 | 12 | Machine gun (Kinetic) | 18 | Fast, captures points 2× faster, wide vision | ✓ |
| APC | Light | 3 | 350 | 8 | Autocannon (Kinetic) | 22 | Tough early unit, captures 3× faster | |
| Light tank | Heavy | 4 | 400 | 9 | 57 mm gun (AP) | 28 | Mobile hunter of light vehicles | ✓ |
| Main battle tank | Heavy | 7 | 900 | 6 | 120 mm gun (AP) | 32 | Backbone. Ammo cook-off on death damages nearby units | ✓ |
| Flame tank | Heavy | 5 | 600 | 6.5 | Flamethrower (Fire) | 12 | Short range, sets ground and trees alight | |
| Self-propelled artillery | Light | 6 | 300 | 5 | Howitzer (HE) | 25–90 | Indirect fire, needs a friendly unit's vision, minimum range | ✓ |
| Rocket launcher (MLRS) | Light | 7 | 280 | 6 | 12-rocket salvo (HE) | 20–70 | Area saturation, long reload | |
| Anti-air vehicle | Light | 4 | 350 | 8 | Flak + missiles (Flak) | 35 | Hard counter to helicopters, weak against ground | |
| Attack helicopter | Air | 6 | 380 | 14 | AT missiles (AP) + rockets (HE) | 30 | Ignores terrain; only Flak and Kinetic hit it well | ✓ |

Rules:

- Weapon cooldowns keep running while moving or retargeting; micro cannot create free shots (V2 rule).
- Turreted vehicles fire while moving; artillery and MLRS must stop to fire.
- Helicopters fly at a fixed altitude and are not blocked by terrain or wrecks. They crash (large explosion) when destroyed.

## 5. Fire support

Strikes are called anywhere on the map, show a **telegraph** (red circle or line) and land after a delay so both sides can react.

| Support | CP | Cooldown | Effect | MVP |
|---|---:|---:|---|:---:|
| Artillery barrage | 5 | 60 s | 12 HE shells over 4 s inside a 20 m circle, 1.5 s telegraph | ✓ |
| Airstrike | 8 | 90 s | Bomber drops a 60 m line of bombs | ✓ |
| Napalm | 6 | 75 s | 25 × 10 m fire zone burning for 8 s | |
| Cruise missile | 10 | 120 s | One huge 15 m blast after a 3 s telegraph | |
| Smoke screen | 2 | 30 s | Blocks vision and targeting through the cloud for 12 s | |
| Repair drop | 4 | 60 s | Restores 40% HP to friendly vehicles in 12 m over 6 s | |
| EMP | 6 | 90 s | Disables vehicles in 15 m for 5 s (no damage) | |
| **Ultimate: Thunderstrike** | — | once per match | Charges from damage dealt. 40 m blast, screen whiteout, shockwave. | |

## 6. Explosions and destruction

This is the main pillar. It must look excessive while costing a bounded amount.

### World construction

- **Terrain:** low-poly heightmap mesh. Craters are decals plus a small local vertex dip (no voxel terrain).
- **Props and buildings:** voxel models, **pre-split into chunks** (for example 4–12 chunks per building). Destruction releases chunks as short-lived physics debris; a destroyed building leaves a rubble mesh. No per-voxel physics.
- **Explosive props:** fuel barrels, ammo crates, fuel depots, gas stations. They have HP; when destroyed they explode and damage their surroundings, which can trigger further props.

### Explosion tiers

| Tier | Examples | Layers |
|---|---|---|
| Small | MG hits, autocannon | Sparks, dust puff |
| Medium | Tank shell, rocket, artillery shell | Flash, fireball, smoke, small debris, scorch decal |
| Large | Vehicle destroyed, barrel | Fireball, rising smoke column, debris, shockwave ring, short light, camera shake, haptic |
| Huge | MBT cook-off, fuel depot, cruise missile | Everything above bigger, secondary pops, burning pieces |
| Ultimate | Thunderstrike | Whiteout, shockwave across the map area, brief slow motion |

### Aftermath

- Wrecks burn for 20–40 s, then smoulder. At most **20 wrecks**; the oldest fade out.
- Scorch decals in a ring buffer of **128**. Burnt trees switch to a charred material.
- Fire spreads over a coarse grid (grass and trees) with a hard cap on burning cells.

### Feel

- Camera shake scaled by explosion size and distance to the camera.
- Haptics on Large and above (setting to disable).
- Slow motion (0.3 s at 30% speed) on MBT death and the ultimate; disabled by the **Reduced motion** setting.
- Layered audio: close explosions crack, distant ones rumble and are muffled.

### Budgets (initial, to be measured on the reference phone)

| Resource | Eco | High |
|---|---:|---:|
| Active pooled effects | 40 | 100 |
| Physics debris chunks | 60 | 200 |
| Dynamic lights from effects | 2 | 8 |
| Scorch decals | 64 | 128 |
| Wrecks | 12 | 20 |

When a budget is full, drop or shorten the **lowest-priority, farthest** visual first. Budgets only ever limit visuals; **damage is always applied by the simulation**, never by an effect (V2 rule 6).

## 7. Controls (touch-first, landscape)

| Action | Gesture |
|---|---|
| Pan camera | One-finger drag on empty ground |
| Zoom | Pinch (clamped; a completed pinch never becomes a tap) |
| Rotate camera | Two-finger twist, snapping to 45°; optional |
| Select one | Tap a vehicle |
| Select many | Long-press, then drag a box; or the **Select all** button |
| Select all of a type | Double-tap a vehicle |
| Control groups | Three group buttons on the side; long-press to assign |
| Move | Tap ground with a selection |
| Focus attack | Tap an enemy with a selection |
| Attack-move / Hold / Retreat / Stop | Command buttons shown for the current selection |
| Deploy / strike | Drag a card from the deck bar; preview shows zone, circle or line; release to confirm, drag back to cancel |

Rules:

- **Retreat** and plain **Move** override automatic targeting until the vehicle arrives (V2 R04). Retreat goes to the drop zone.
- UI never passes input through to the battlefield.
- Minimum touch target 44 × 44 pt; respect safe areas and notches.
- Command buttons never move or resize when their state changes.
- Mouse and keyboard work in the editor for testing only.

## 8. Maps

Maps are data (`MapDefinition` JSON): size, heightmap seed or file, drop zones, capture points, HQ positions, prop and explosive-prop placement, roads, rivers and bridges.

**MVP map, "Ashfield":** 160 × 160 m, three capture points (west farm, central town, east fuel depot), a destructible town in the middle, a river with two bridges, and forest patches. Later maps vary size (128–256 m), palette (desert, snow, forest, industrial) and objective layout.

### Navigation

- Pure C# **grid navigation** in the simulation: 2 m cells, A* for single vehicles and a flow field for groups sharing a destination.
- Buildings block cells; destroyed buildings become rubble, which slows movement instead of blocking it. Large wrecks block, small wrecks do not.
- Heavy vehicles use their full footprint on bridges and in narrow streets.
- An unreachable destination resolves to the nearest reachable cell.
- Unity NavMesh is a fallback only if grid navigation proves too slow.

## 9. AI opponent

- Uses the same commands as the player: deploy, move, attack, strike.
- Utility-based decisions every 0.5–1 s: choose an objective (take an uncontested point, defend a threatened one, push the weakest), pick counters to what it has seen, strike clusters of 3 or more vehicles, pull back badly damaged heavy vehicles.
- Difficulty (Easy, Normal, Hard) changes decision interval, counter-picking quality and strike accuracy. No hidden CP or free units by default; any bonus is disclosed in the difficulty description.
- Once fog of war exists (Phase 5), the AI only knows what it has seen.

## 10. Architecture

### Rules kept from V2

1. The simulation is authoritative and independent of rendering. Views, effects and UI never own HP, CP, damage or objective state.
2. Fixed simulation step, initially **20 Hz**, with interpolation for presentation. Bound catch-up after a pause.
3. Entities have **stable IDs plus a match generation**, so callbacks from a previous match cannot act on the current one.
4. Commands are explicit data (type, owner, entity IDs, target, queue/replace). Validate when submitted **and** when executed.
5. The simulation emits events (shot, hit, damage, destroyed, captured, strike landed). Effects and audio consume events and never apply damage.
6. A player order is distinct from an automatic target. Automatic targeting cannot override Move or Retreat.
7. After a match result, reject all gameplay commands. Pause stops the simulation and CP income.
8. UI buttons, gestures, AI and modes all use the same command path.
9. Restart resets every entity, effect, pool, selection and the camera, and bumps the match generation.

### Layers and folders

```text
MachineBrigade/                         Unity project and git repository (outside OneDrive)
  Assets/MachineBrigade/
    Scripts/
      Sim/                         MachineBrigade.Sim.asmdef, noEngineReferences = true
        Core/  Commands/  Entities/  Combat/  Navigation/
        Economy/  Strikes/  Modes/  AI/  Events/
      Voxel/                       MachineBrigade.Voxel.asmdef: model format, greedy mesher, chunk splitting
      Game/                        MachineBrigade.Game.asmdef: MonoBehaviours
        Match/     MatchRunner (composition root, drives sim ticks)
        Views/     vehicle/prop views interpolating sim snapshots
        Effects/   EffectsDirector, pools, shake, haptics, audio
        Input/     touch gestures -> commands
        Camera/  Hud/  Screens/  Services/ (settings, save, localization)
      Editor/                      asset generators, BuildScripts (Android AAB, iOS Xcode project)
    Content/
      Data/        balance.json, modes.json, maps/*.json (versioned, text-editable)
      Models/      voxel sources generated by code
      Materials/  Audio/  Fonts/ (Be Vietnam Pro, Vietnamese glyphs)  Localization/
    Scenes/        Boot.unity, Match.unity, PerfTest.unity (kept minimal; content spawned from code)
    Tests/
      EditMode/    simulation tests, no scene needed
      PlayMode/    smoke tests: boot, run a match for 60 s, restart
  Docs/            GAME_PLAN.md, RELEASE.md, PRIVACY.md, reference RTS plans
```

- `Sim` has no `UnityEngine` reference. It uses `System.Numerics`, plain classes and a seeded RNG, so it runs in EditMode tests and could later run on a server.
- Balance, modes and maps are JSON loaded into plain definition objects at match start. ScriptableObjects are used only on the Game side to map a definition ID to its model, effects and sounds.
- Everything in a match (map, vehicles, props) is spawned from code and data. Scenes hold only the camera, light and bootstrap object, which keeps them easy to review and merge.

### Packages

URP, Input System (EnhancedTouch), Localization (which pulls in Addressables), Test Framework, uGUI with TextMeshPro. Add Burst/Collections/Mathematics only if profiling shows voxel meshing or navigation needs them. No DI framework, no third-party state libraries.

### Coding conventions (adapted from Sticky-Wall)

- One concept per file; keep files under about 400 lines. Split before a file grows into a 2,000-line screen.
- `///` XML doc comments on public types and members, explaining *why*.
- Plain C# classes and events; dependencies passed through constructors from a composition root (`MatchRunner`, `Boot`), the same idea as Sticky-Wall's `main.dart`.
- Definitions are immutable (`readonly`, init-only); mutable state lives only in the simulation.
- `#nullable enable` at the top of every `Sim` file; keep the whole project free of compiler warnings.
- Platform services (haptics, file IO, store APIs) wrap work in try/catch and log a warning, so they degrade safely in the editor and tests.
- Loading data is tolerant: skip a malformed record, log it, keep the rest.
- No hard-coded player-facing text; everything goes through the localization tables (en, vi).
- Saves are JSON in `Application.persistentDataPath`. No backend, no data collection.

### Carried from V2

| R01 | Vehicles and helicopters are easy to tap without an oversized area stealing neighbours |
| R03 | Camera reaches all four map corners at near and far zoom, with HUD visible |

| R12 | Navigation respects new wrecks, destroyed buildings, bridges and explicit ignore lists |
| R13 | With fog enabled, the AI only uses what it has seen |
| R14 | A defeated side stops producing, striking and fighting; all references are cleared |

| ID | Acceptance case |
|---|---|
| T01 | Damage is applied exactly once per hit; effects and debris never deal damage |
| T02 | Exceeding an effect budget drops visuals only; simulation results are identical with effects on or off |

## 13. Build and release

- Editor script `BuildScripts` provides command-line builds (`-batchmode -executeMethod`) for an Android AAB and an iOS Xcode project. The editor must be closed for batch builds.
- Version: `bundleVersion` for players, `versionCode` / build number bumped on every store upload.
- The Android keystore and its passwords live outside the repository, like Sticky-Wall's `key.properties`.
- Android: IL2CPP, ARM64, Vulkan with OpenGL ES 3 fallback.
- iOS: the Xcode project can be generated on Windows; compiling, signing and uploading require a Mac with Xcode and an Apple Developer account.
- Google Play: same checklist as Sticky-Wall's README (privacy policy URL, Data safety "no data collected", content rating, closed test with 12 testers for 14 days on new personal accounts).
